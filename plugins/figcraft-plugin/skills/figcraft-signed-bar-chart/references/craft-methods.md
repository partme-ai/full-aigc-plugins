# 含正负与零值的可编辑柱状图：CLI/MCP方法

按[具体步骤和参数](craft-steps.json)逐步执行，完整实际枚举在[命令记录](craft-command-evidence.json)。创建动作先查询已有文件与名称，现有内容不可初始化。每个capture均为真实回执：node/instance/collection/variable返回的ID类型不同，原样使用，不拼接或假设为连续数字。

CLI可以使用本技能独立附带的run_recipe.py：以宿主实际技能安装目录定位脚本，使用`--cli`指定已核实的可执行程序，`--output`为不存在的新.figcraft路径，已有输入用`--input`。没有任何其他技能目录依赖；执行器只串行调用原生命令并绑定返回值，不计算业务效果。也可用`figcraft-cli run 命令数组.json --in 原文件 --out 新文件`手动分批，在捕获返回ID后生成下个数组；原生CLI不会解析$ref标记。

插件MCP服务为`figcraft-editor`，先读取实际工具schema：`run_command {"command":"node.get","params":{"id":实际返回ID}}`。该会话的ID与独立CLI文件不同。当前Web支持与否须实际调用核实，不能由原生目录推断。`open_file`/`save_file`按当前schema的path完成同会话可编辑文件交付，`export`只生成派生图；完整文件及PNG/SVG均检查实际写入回执与新路径存在。不要直接假设浏览器虚拟路径等于工作区路径。

正负柱以零基线分开、零值有标签且高度为0，类目与值一一对应；修改数据后按同一量程重算所有柱和基线，标签保持可编辑，SVG与PNG体现正确方向。

这是可编辑形状和文字，不是带自动数据绑定的图表控件。数据来源/单位/期间必须由任务核实；不接受NaN/无穷/缺失冒充0。全零用[-1,1]示意区间防除零，标签写0，不添加假柱高。

新增节点/组件可能位于画板外作为定义，给已有文件追加时先检查实际空白区域并调整全部相关坐标，保留用户原节点、主组件和变量。原文件摘要不能变化；新文件重开后检查同样的ID关联、值和几何。图层存在或导出成功不代表设计质量、可访问性或Figma兼容性已验收。

## 任意数据的几何映射

按数据序保持类目和值配对，先拒绝空数组、布尔、字符串、缺失、NaN与无穷。取lo=min(0,最小值)、hi=max(0,最大值)，全零时改为lo=-1、hi=1。绘图区上边T=200、高H=600；Y(v)=T+(hi-v)/(hi-lo)*H，零基线Y(0)。每个柱的y=min(Y(v),Y(0))，height=abs(Y(v)-Y(0))，x按同宽类目槽排列；零柱height=0且保留0标签。示例[-20,0,40,80]量程[-20,80]、零基线680；不是只改变单柱高度。修改数据后同时更新所有柱的y/height、值标签位置/文字、pluginData中的value及零基线，保持同一量程；不可截断负值或用非零最小柱高夸大零值。

## 交付及限定验证

独立Python入口以ASCII转义JSON输出回执，接收方用JSON解析恢复中文路径与文本；不能把转义序列当成真实文件名。脚本在非UTF-8输出环境也不能因打印回执而把已完成的原生操作报告为失败。已有场景手册执行器也采用相同输出方式。

本批合成示例的macOS、Windows原生命令回归通过；真实Codex MCP已逐条执行同一配方并在内嵌编辑器观察更改。修改后另存，七个实际宿主文件由独立CLI回读；全零柱图另开新路径副本，open_file实际解析新文档，重导出PNG像素保持。此范围不代表真实业务设计质量、全部旧场景交互或其他宿主已验收。

# 表格清洗


执行具体方法前读取 [Craft 场景命令与参数](references/craft-methods.md)，按其中的对象选择、会话、输入替换和结果检查执行。

## 任务起点

先读取素材，确认交付用途、目标尺寸或时长、修改范围与必要格式。能从任务和素材确定的细节直接采用合理默认值；只询问会改变结果的缺失条件。

需要可见编辑器时交给 **gridcraft-editor** 技能。独立安装：`npx skills add full-aigc-skills/gridcraft-skills --skill gridcraft-editor`。当前新增技能为本地候选，发布前使用本地配套插件，不把此安装命令当作已发布证明。

## 执行步骤

1. 保留原始表，在工作副本中识别字段类型和主键。
2. 统一日期、单位和空白字符，避免把编号转成数字。
3. 按明确规则标记重复和缺失，不凭猜测填充。
4. 汇总清洗前后行数和异常项。

先确认输出空白，再将目标主键列设为文本后拆列，保留前导零；默认只删除完全相同的整行，主键冲突留待复核。

## 工具落地

用 open_workbook/new_workbook 管理工作簿；read_range 检查、set_cell 编辑，execute_command 使用完整命令；save_workbook 保存。

先读取实际工具 schema，再填写参数；对象或文档 ID 使用返回值。查询到的命令必须在当前后端可用。保存前选择新输出路径，保留输入。需要的算法、格式或命令不存在时说明缺口，不能用相近名称冒充。

## 结果检查

- 长编号、前导零和日期未变形。
- 删除或合并的记录能对应回原始行。
- 公式区与数据区分开，输出可重开。

对照用户目标检查实际内容，而不只检查进程退出码。局部编辑查看局部细节，版式任务查看整页，时间媒体查看起止与关键段。异常结果先检查当前工程，避免重复执行不可逆操作。

## 交付

返回可编辑工程、实际派生文件和简短说明：做了哪些修改、哪些步骤因当前能力未执行、需要用户判断的内容。只列真实存在且已经检查的文件。若用户随后返工，读取本次源工程并局部修改，保留已接受的内容。

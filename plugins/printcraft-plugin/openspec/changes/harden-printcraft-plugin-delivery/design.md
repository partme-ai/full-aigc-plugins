## Context

当前插件 0.1.0-dev.1 包含与技能源完全一致的 36 个技能文件，另有最小 plugin.json、candidate-source.json、文档和一个快照测试。48 个项目文件在上轮分析中保持不变；测试 1/1 通过不代表宿主验收。

反向校验已在临时副本复现：非空 releaseTag、错误 sourceProject/sourceVersion 和数字 manifest.version 均被接受。插件本身没有 MCP 配置、宿主专用清单或独立 Harness。

## Goals / Non-Goals

目标：准确识别来源，保持上游快照与本地扩展分离，以薄 Harness 消费技能源契约，逐层验证当前 Codex 环境的真实发现、选择和 PDF 任务。

非目标：重写 PDF 引擎或技能源 Python 执行器；自动发布/安装；默认所有宿主兼容；复制 Dreamina 登录、积分、远端 submitId；将清单可解析等同于真实宿主加载。

## Decisions

### 1. 两项目规格归属

| 内容 | 唯一事实源 |
|---|---|
| 六技能、运行时、执行/恢复、PDF 验收、原生证据 | printcraft-skills / harden-printcraft-skill-execution |
| 来源锁、插件本地 Harness、宿主、分发更新 | 本 change |

依赖项：上游 RT-01～04、EX-01～05、PV-01～04、AE-01～03。Harness 只通过公开契约消费，不导入兄弟工程路径或私有函数。上游未完成不阻塞来源校验和清单测试；真实 Harness 闭环依赖上游协议。

### 2. 候选和正式来源分开建模

候选保留 candidate-source.json，但验证来源项目/版本、releaseTag=null 和精确摘要。正式来源另用明确版本的发布锁，绑定仓库、tag、commit、技能版本、文件清单与摘要；不把候选改个字符串就当作正式来源。源版本和插件版本允许独立，但映射必须显式且可核验。

上游精确技能清单与插件本地白名单分离，新增 printcraft-harness 在白名单中声明。校验器执行真实字段/类型/版本规则和组件存在性检查，不仅比较 schema URI。离线完整性与正式远端来源验证分开报告。

### 3. 薄 Harness 和宿主首验

Harness 管理路由、显示、交接、用户已有授权和验收状态；状态与执行仍由上游公共入口维护。它消费 `printcraft.execution/1` 和 `printcraft.verification/1`（由上游 change 定义），不接受未知协议静默降级。

首个实际验收目标选择当前 Codex 环境；其他宿主只登记矩阵，未来逐项添加证据。portable 清单为规范来源，必要兼容文件由生成器输出，使用实际宿主版本的支持方式验证。当前没有已验收安装，因此不能凭参考仓库中的命令写死永久宿主安装语法。

```mermaid
flowchart LR
    S[已核验技能源] --> L[来源锁与受管清单]
    L --> V[快照与本地技能验证]
    V --> M[生成宿主清单]
    M --> H[全新宿主发现和加载]
    H --> R[自然语言及显式路由]
    R --> E[消费上游执行契约]
    E --> P[真实 PDF 与验收回执]
    P --> G[发行门禁与已有授权检查]
```

### 4. 发布与历史证据

本地快照测试、分发校验、宿主加载、模型选择、原生 PDF、发布/更新分开记录。证据必须绑定当前版本和实际快照，不能仅复制 Dreamina 的 PASS。只有明确授权后才能创建 Git/远端、安装插件、发布或同步市场。

同步入口位于技能源 scripts/sync_local_snapshot.py，插件文档必须标明所有者；运行时绝不依赖此开发路径。正式更新保留用户任务状态，不兼容状态只能只读，不通过降级解释器自动恢复。

## Risks / Trade-offs

- 初期只验收一个宿主 → 明确支持矩阵，避免虚假多宿主承诺。
- 上游回执尚未实现 → 先以协议夹具建立消费者拒绝测试，真实集成任务保持开放。
- 来源文件和摘要同时被修改可绕过纯本地完整性 → 正式发行绑定独立可核验 commit/tag，不把 SHA-256 当作来源认证。
- 无 Git/远端 → 候选开发可以继续，正式锁与发行验收保持待授权，不伪造提交身份。
- 本地 Harness 增加技能数量 → 明确 managed/local 两类清单，不改写“六项上游技能”为七项。

## Migration Plan

先修来源和 manifest 拒绝测试，随后增加本地白名单和保护性同步；上游协议完成后接 Harness。生成目标宿主包、授权隔离安装、真实模型与 PDF 场景验收、核验正式来源后才进入授权发布。旧候选不强制覆盖，回退仅替换可兼容程序包且保留任务数据。

本次只记录未来步骤；未实现任务不勾选，不同步主规格、不归档。

### 显式外部中文 OCR 后端的来源升级

用户已授权 Tesseract 可选后端。插件从新的不可变技能源发行同步 ocr.py 与简繁中文使用契约，保持原生 0.2.1、不安装外部依赖、不透明回退。锁记录新技能源 tag/commit/suite/全部文件摘要，本地 harness 保留。新增 printcraft.ocr/1、printcraft.ocr-backend/1 与 execution/verification 分开。真实中文证据只证明指定 Tesseract/模型/macOS arm64 组合，不追认原生中文支持或手机验收；旧 dev.5 制品保持不变。

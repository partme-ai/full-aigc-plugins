# PDF 表单填写


执行具体方法前读取 [Craft 场景命令与参数](references/craft-methods.md)，按其中的对象选择、会话、输入替换和结果检查执行。

## 任务起点

先读取素材，确认交付用途、目标尺寸或时长、修改范围与必要格式。能从任务和素材确定的细节直接采用合理默认值；只询问会改变结果的缺失条件。

需要可见编辑器时交给 **pdfcraft-editor** 技能。独立安装：`npx skills add full-aigc-skills/pdfcraft-skills --skill pdfcraft-editor`。当前新增技能为本地候选，发布前使用本地配套插件，不把此安装命令当作已发布证明。

## 执行步骤

1. 读取字段名、类型和可选值，映射用户提供的数据。
2. 对缺失信息保留空白或待确认，不猜测填写。
3. 填写后检查多行文本、字体及勾选状态。
4. 按要求保留可编辑字段或输出扁平副本。

字段值与显示外观必须分别验收。当前官方0.8.0在Helvetica表单填写中文时有外观显示为????的已复现限制，不能把存储成功当作中文填写完成。

## 工具落地

上游工具名属于 PdfCraft。doc_open/doc_create 返回 doc 句柄；后续 doc_info、doc_save、page_render 使用同一 doc。PDF 页号从 1 开始，参数以实际 schema 为准。

先读取实际工具 schema，再填写参数；对象或文档 ID 使用返回值。查询到的命令必须在当前后端可用。保存前选择新输出路径，保留输入。需要的算法、格式或命令不存在时说明缺口，不能用相近名称冒充。

## 结果检查

- 姓名、日期、金额逐项对照输入。
- 扁平化不等于数字签名。
- 重开文件确认字段值与视觉显示一致。

对照用户目标检查实际内容，而不只检查进程退出码。局部编辑查看局部细节，版式任务查看整页，时间媒体查看起止与关键段。异常结果先检查当前工程，避免重复执行不可逆操作。

## 交付

返回可编辑工程、实际派生文件和简短说明：做了哪些修改、哪些步骤因当前能力未执行、需要用户判断的内容。只列真实存在且已经检查的文件。若用户随后返工，读取本次源工程并局部修改，保留已接受的内容。

## 技能商店场景经验

遇到先发现字段再填写时，读取[商店工作流适配](references/market-workflows.md)，使用对应的Craft方法和实际结果检查。上游技能不作为运行依赖。

## 从真实字段生成填写请求

本技能自带 `scripts/form_request.py`，无需安装其他技能。保存当前会话 `form_fields` 的原始JSON为fields.json，将用户明确提供的字段值写入values.json，例如 `{"customer.name":"张三","consent":false}`；字段名必须与本次返回完全一致，示例名称不能直接套用。

```bash
python3 <本技能目录>/scripts/form_request.py --fields fields.json --values values.json --doc 7 --output request.json
```

`7`须替换为本次 `doc_open` 实际返回的ID。工具仅生成同会话 `form_fill` 请求，不操作PDF、不打开新CLI进程，也不确认快照属于哪个文件；执行前核对文档身份和字段快照仍有效。支持文本与复选框，拒绝不存在、重名、只读或可写性未知的字段；签名、按钮及其他字段类型须按实际原生schema另行处理。文本逐字保留，不擅自清洗或转拼音。只校验本次明确填写的字段，不声称整份表单已经完整填写。

执行返回的 `tool` 和 `arguments` 后，检查 warnings；保存新路径，再重开比较字段值并渲染受影响页。中文存储正确但外观为问号仍属未完成，不能拿本辅助工具的校验通过替代页面验收。计划输出采用独占创建，不覆盖已有文件。

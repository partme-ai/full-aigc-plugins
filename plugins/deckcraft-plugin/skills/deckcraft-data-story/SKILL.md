# 数据叙事演示


执行具体方法前读取 [Craft 场景命令与参数](references/craft-methods.md)，按其中的对象选择、会话、输入替换和结果检查执行。

## 任务起点

先读取素材，确认交付用途、目标尺寸或时长、修改范围与必要格式。能从任务和素材确定的细节直接采用合理默认值；只询问会改变结果的缺失条件。

需要可见编辑器时交给 **deckcraft-editor** 技能。独立安装：`npx skills add full-aigc-skills/deckcraft-skills --skill deckcraft-editor`。当前新增技能为本地候选，发布前使用本地配套插件，不把此安装命令当作已发布证明。

## 从真实数据生成命令计划

使用本技能自带的 `scripts/data_story.py`，不依赖其他技能脚本：

```bash
python3 <本技能目录>/scripts/data_story.py --input data.json --output plan.json
```

输入结构见 [可填写示例](assets/example-input.json)。`title` 为用户提供、待核实的结论；`unit`、`period`、`source`、`definition`、`limitations`、`action` 必填。保留类别顺序，2至12类、1至3组同口径数值；拒绝缺失值、重复类别、布尔值及非有限数值，不能把缺失值补零。编译器不验证来源真假，也不推断因果。标题较长时仍需预览调整。

计划仅限新建文稿，含 `file.new`，不得对现有编辑会话直接执行。确认新建后，CLI 用 argv 逐项传入 `run --cmd <command>=<JSON params> --save <新路径>`；需要同步画面时，经编辑器就绪后的同一会话逐条 `run_command`，不能另起 CLI 冒充同步。输出计划使用独占创建，不覆盖现有文件。

图表保存为原生分类柱状图；数据点总数大于12时默认关闭数值标签，以减少稠密标签重叠，精确值保留在可编辑图表数据中。仍需检查相同值或长标签的布局。单位进入标题，期间、来源、口径与解释边界进入逐页备注。保存后检查图表数值和备注，并预览所有页面；真实图表轴、字体和投影效果仍需单独验收。

## 执行步骤

1. 核对指标定义、期间和筛选范围。
2. 先写结论，再挑最能支撑结论的图表。
3. 突出关键变化并注明基线，异常点增加解释。
4. 最后给出可由数据支持的行动建议。

## 工具落地

用 open_presentation/new_presentation 管理演示文稿；add_slide、inspect_slide、inspect_document 操作和核对；save_presentation 保存。

先读取实际工具 schema，再填写参数；对象或文档 ID 使用返回值。查询到的命令必须在当前后端可用。保存前选择新输出路径，保留输入。需要的算法、格式或命令不存在时说明缺口，不能用相近名称冒充。

## 结果检查

- 图表轴与数值准确，缺失值不画成零。
- 相关性不写成因果。
- 每页结论与证据一致。

对照用户目标检查实际内容，而不只检查进程退出码。局部编辑查看局部细节，版式任务查看整页，时间媒体查看起止与关键段。异常结果先检查当前工程，避免重复执行不可逆操作。

## 交付

返回可编辑工程、实际派生文件和简短说明：做了哪些修改、哪些步骤因当前能力未执行、需要用户判断的内容。只列真实存在且已经检查的文件。若用户随后返工，读取本次源工程并局部修改，保留已接受的内容。

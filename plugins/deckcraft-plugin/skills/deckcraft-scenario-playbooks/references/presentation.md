# DeckCraft presentation 场景

默认从新建空文件执行。按实际输入替换示例，已有文件先定位目标；不要清空或全选已有文稿。组合演示场景只新建一次，后续跳过带newDocumentOnly标记的步骤。

## demo-problem-result：产品演示的问题与结果叙事

输入：已验证的用户问题、演示步骤与可观察结果；保留已知限制。

| 操作目的 | 命令 | 参数例子 |
| --- | --- | --- |
| 1. 新建960×540点空演示文稿，仅在新建任务中使用 | `file.new` | `{"size":[960,540],"blank":true}` |
| 2. 建立按信息结构选择的标题内容页 | `slide.new` | `{"layout":"titleAndContent","title":"用户问题","body":"资料编号重复，人工核对成本高。"}` |
| 3. 记录首屏讲述目标 | `slide.notes` | `{"text":"先解释输入与问题，不先堆功能。"}` |
| 4. 建立按信息结构选择的标题内容页 | `slide.new` | `{"layout":"titleAndContent","title":"演示步骤","body":"导入资料 → 检查编号 → 定位重复项。"}` |
| 5. 记录演示输入与预期 | `slide.notes` | `{"text":"使用已授权的演示数据，不展示私人资料。"}` |
| 6. 建立按信息结构选择的标题内容页 | `slide.new` | `{"layout":"titleAndContent","title":"结果与限制","body":"定位重复项；是否删除由使用者复核。"}` |

检查：版心内无溢出与遮挡；备注记录来源与待确认假设；保存源工程、导出PPTX后核对可编辑对象。

边界：不能把计划能力写成已完成结果；实际演示需预演并检查页面信息密度。

## speaker-handoff-notes：可交接的演讲备注稿

输入：讲者需接手演示，提供每页目标、用时、来源与转场提示。

| 操作目的 | 命令 | 参数例子 |
| --- | --- | --- |
| 1. 新建960×540点空演示文稿，仅在新建任务中使用 | `file.new` | `{"size":[960,540],"blank":true}` |
| 2. 建立按信息结构选择的标题内容页 | `slide.new` | `{"layout":"titleAndContent","title":"项目进展","body":"本期完成目录整理。"}` |
| 3. 备注明确目标和转场 | `slide.notes` | `{"text":"目标：说明范围。用时：1分钟。来源：项目台账。转场：解释剩余缺件。"}` |
| 4. 建立按信息结构选择的标题内容页 | `slide.new` | `{"layout":"titleAndContent","title":"风险与下一步","body":"缺件核验完成后进入最终复核。"}` |
| 5. 备注保留行动与责任边界 | `slide.notes` | `{"text":"目标：请求补齐输入。用时：1分钟。来源：缺件清单。结尾：确认负责人和期限。"}` |

检查：版心内无溢出与遮挡；备注记录来源与待确认假设；保存源工程、导出PPTX后核对可编辑对象。

边界：备注不是已发送通知或批准事项；责任人与期限必须现场或从真实输入确认。

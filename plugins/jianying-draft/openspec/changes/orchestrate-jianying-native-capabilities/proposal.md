## Why

当前 Harness 能编译通用剪辑 Job，但没有把剪映自带的视频/图片、音乐、文字、贴纸、特效、转场、字幕、智能包装、滤镜、调节、模板和数字人纳入统一发现、筛选和执行闭环。结果是智能体只能做基础时间线编辑，无法根据内容目标灵活使用用户已经拥有的剪映专业能力。

## What Changes

- 建立剪映原生能力目录，区分资源、参数化编辑工具、AI 组合能力和生成型数字人能力。
- 扩展 WorkflowPlan，使每一步能够声明资源查询、候选筛选、权益/费用/肖像门禁、应用动作、结果证据和回滚动作。
- 为官方视频/图片、音乐、文字模板、贴纸、特效、转场、字幕样式、滤镜、调节和模板建立统一路由。
- 为智能包装、智能 B-Roll 和数字人建立专用编排，不把它们降级为普通素材下载。
- 插件只编排发布 Rust CLI 的稳定命令和宿主批准的 GUI Adapter；不从 Rust 源码推断能力。
- 在真实剪映、基础版/专业版、费用、许可证、肖像与发布渠道边界上 fail closed。
- 从不可变 `jianying-skills` 发布锁定消费 13 个面板分类技能，使智能体能够从功能入口进入逐动作动线，而不是依赖一份总说明。

## Impact

- `WorkflowPlan`、步骤合同、能力映射、Harness 路由和质量循环增加原生能力步骤。
- 插件锁定消费 CLI 的版型、权益、官方资源与原生执行命令。
- 真实 GUI 操作通过宿主 Adapter 执行，但所有选择、审批、证据与状态由插件和 CLI 的机器合同约束。
- 数字人和 AI 包装可能产生上传、模型调用、费用及肖像风险，必须使用独立批准和账本。
- 技能正文仍由 `jianying-skills` 单向发布；插件只负责锁定导入、Harness 编排和三宿主可见性。
